# Chrono Desk 0.4.4 — complete late photo bursts

Task: CHR-CAM-004
Docs-Impact: LOCAL

## Change

Chrono Cam saves/publishes a track after its first JPEG, then appends the rest of
the burst. Previous Desk versions froze `frames_json` on first ingest, leaving
an album permanently partial when the first poll arrived during capture.

Desk now merges the received frames in the same SQLite transaction that reads
the existing series and updates display metadata. Frame identity is scoped to
one source-qualified track; v1 `/photo?path=...` uses the immutable photo path,
so reconnecting with another phone address does not duplicate the same JPEG.
Other URLs retain exact-URL identity. Distinct frames with equal timestamps
remain distinct. Frames are ordered by timestamp; duplicates, empty or shorter
snapshots do not remove saved evidence. Invalid frame lists fail without changing
the stored row.

Track time and all existing frame times remain unchanged. Newly added frames
are rebased by `stored_track_time - incoming_track_time` because incoming track
and frame times share the same newly measured LAN offset. This retains the
first-ingest calibration rather than mixing different clock estimates in a
single burst. This is not a new clock-accuracy guarantee or an official timing
correction.

## Compatibility and recovery

- No database migration, phone API change or Android update.
- No changes to bib confirmation, multi-camera grouping, RFID observations,
  official results, timing-core, sync ownership or outbound journals.
- Existing partial albums can be repaired by a full poll if the registered phone
  still holds and serves the same event. Repeated pulls are idempotent.
- `since_ms` remains a creation-time cursor. A newer track can move it past an
  older unfinished burst; periodic full refresh (every ten cycles, nominally
  about 30 seconds) or explicit full polling picks up those late frames.
- JPEG caching remains lazy. Complete metadata does not mean every JPEG has been
  copied to the computer. This release does not create a full photo backup.

## Regression coverage

Storage tests cover initial snapshots with 0/1/3/4/8 frames, expansion to eight,
duplicate and reverse-ordered input, stale/empty snapshots, changing clock
offset, concurrent partial writers, invalid JSON, changed phone address and
distinct same-time frames. The HTTP-poller/SQLite integration test reproduces a
three-frame older track skipped by incremental polling, then completed by a full
refresh with and without a database/process restart. It also checks late OCR and
the merged-wall album's stored frame list.

## Field verification and rollback

Before updating the competition computer, retain its current app and a coherent
backup of the event database (close the app before copying SQLite files).
Install the new Desk build, leave the phone on the original event with LAN sync
enabled, and allow/trigger a full poll. Reopen an affected album and compare its
frame count with the same track on the phone. Verify that previously selected
times remain unchanged. A disconnected phone cannot repair absent frames.

The schema is unchanged and previous versions can read the enlarged frame lists;
keep the application/database rollback pair according to the existing field
runbook. Native build success does not replace execution on the competition Mac.
The existing Go 1.24/macOS 11 security exception in
[architecture](../architecture.md#build--platforms) remains unchanged.
