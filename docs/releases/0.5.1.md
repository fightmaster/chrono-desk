# Chrono Desk 0.5.1 — ordinary Feibot and RFID Edge reception

Task: CHR-SIDE-002
Docs-Impact: OPERATIONAL

## Change

The ordinary **Запустить приём** action on the existing Feibot port now accepts
both the vendor Feibot JSON and the owned RFID Edge v1 envelope. A normal
Feibot setup no longer requires copying a sidecar session, adding a device,
choosing a second port or saving a separate Edge form. The request contains
only the existing listener port; the event opened in Desk remains authoritative.

RFID Edge supplies its selected numeric event as the source session. Desk
accepts that automatic Feibot source only when packet event and session match
the open event. Explicit Board/plate sources, source revocation and a separate
generic listener remain in the collapsed advanced section and keep their
fail-closed binding rules.

Raw Edge observations are persisted without requiring a timing checkpoint.
They do not create results until the event's checkpoint configuration permits
calculation. Antenna/port and immutable source metadata remain available for
later mapping and replay.

## Compatibility and rollout

- Native Feibot JSON and existing event databases remain supported.
- This release contains no packet-issuance feature ancestry.
- Install receiver changes first: publish the matching `rfid-core`, then update
  RUN5/RFID Hub admission, Chrono Desk and finally RFID Edge on the appliance.
- Edge delivery to Desk follows the address and port configured in the Feibot
  UI. Hub address and mTLS identity remain one-time installation settings.
- Keep the previous Desk application and a coherent event-database backup for
  rollback. Do not release held historical appliance queues during acceptance.
