# Chrono Desk 0.6.14

Task: CHR-CUT-002
Docs-Impact: CROSS_PROJECT

This compatibility release aligns Desk with the central Go replacement's
published `timing-core v0.11.0` (source
`65793ffc88f3466b875293af58c04996d2b55bfc`). It keeps the established strict
fixed-distance snapshot API and the existing shared processor/ranking paths.

Vite is updated from 8.2.2 to patched 8.2.4 after the release audit found
a high-severity development-server advisory. Svelte, the Node compatibility
range and the Safari 14 output target remain unchanged.

There are no new UI functions, event-file migrations, sync payload versions or
changes to reader/camera reception. Existing v3 push and v1 pull remain compatible
with the current RUN5 receiver. The version endpoint reports the new library.
Manual decisions, disabled observations and outbound ownership remain unchanged.

Desk already supports participant-scoped planned replay. This release does not
activate core 0.11's new merged-projection API, add Stopwatch support or claim
further performance gains. See [adoption boundaries](../timing-core-0.11-adoption.md).

Go remains 1.24.13 for Intel macOS 11; the existing CHR-SEC-002 standard-library
security debt is not resolved by updating timing-core. Native packaging is done
by the existing tag workflow after the compatibility gates; publishing source
alone does not mean an app has been installed on the working Mac.

The 2026-10-21 vulnerability audit reports 25 reachable standard-library findings
on Go 1.24.13, plus 6 imported-package and 37 module findings without vulnerable
calls. An unchanged v0.6.13 baseline audited with the same current database has
the identical findings; the timing-core update introduces no additional reported
finding. This is recorded CHR-SEC-002 debt, not a clean security audit.
