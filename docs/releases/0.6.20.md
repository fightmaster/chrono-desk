# Chrono Desk 0.6.20

Task: CHR-SYNC-001. Docs-Impact: LOCAL.

Manual site delivery now drains new owned observations in sequential batches of
at most1,000, displaying progress after durable acknowledgements. Completed
batches remain acknowledged after interruption; retrying a previously sealed
batch retains its original identity and range. Imported site observations are
never added to the owned outbound journal. One action is bounded to100 batches;
remaining work can be continued by another action.

HTTP429 retries respect Retry-After and replay the exact body, with bounded retry
count and request timeout. Other HTTP/ambiguous transport errors retain their
existing failure behavior. Background pull and local Live do not imply automatic
native observation push; site delivery remains an explicit action.

Observation identity, v3 wire/ACK contracts and server batch compatibility remain
unchanged. RUN5's separate polling/push budgets are a compatible server fix.
No raw timing correction, event recount or reader activation is performed.

macOS11 Intel packaging retains Go1.24.13; its existing standard-library security
debt remains CHR-SEC-002. This release does not claim that debt is resolved.
Installing the app and physical backlog/live-latency acceptance remain separate
from publishing source and platform artifacts.

See [delivery behavior and tests](../site-delivery-backlog.md).
