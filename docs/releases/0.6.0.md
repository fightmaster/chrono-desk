# Chrono Desk 0.6.0 — packet issuance receiver

Task: CHR-SW-009 (within CHR-SW-006)
Docs-Impact: CROSS_PROJECT

Status: local release candidate; not published or physically accepted

## Change

Chrono Desk can act as an additional local source and receiver for the
Stopwatch PWA packet-issuance mode. After the event has been connected to
chrono.events, the operator enables the separate HTTPS packet receiver and
creates one scoped invitation per tablet. The site remains authoritative;
Desk retains its own immutable registration-change journal and relays the
common bootstrap, operation, feed and conflict-resolution contracts without
converting tablet actions into timing observations.

The enabled event, grants, feed cursor, incoming actions and pending-safe
snapshot rebase survive application restart. A bounded, explicit compaction
path archives old feed prefixes only after reception is stopped and all tablet
access is revoked. No packet history is deleted automatically.

This candidate also includes the 0.5.1 ordinary Feibot/RFID Edge reception
baseline. The normal Feibot workflow still uses the existing listener and does
not require Edge session, device or second-port setup.

## Operator boundary

- The ordinary source is chrono.events; file import remains supplementary.
- Packet LAN is off by default and separate from the localhost control API and
  public results broadcast.
- Each tablet gets an independent short-lived pairing invitation and durable
  scoped credential. Site and Desk credentials are not interchangeable.
- First use requires installing and explicitly trusting the Desk local CA on
  the tablet. Certificate bypass is not an accepted workflow.
- Starting packet LAN advertises `chrono-desk.local` by mDNS. Stopping it closes
  HTTPS and mDNS; a previously enabled event resumes after a Desk restart.
- Revocation prevents later network access but never erases data already saved
  on the tablet.

## Compatibility and rollout

Deploy the additive RUN5 receiver with its capability disabled before this
Desk release. Install this candidate on a rehearsal copy, then publish the
Stopwatch PWA candidate and enable the capability for one pilot event only.
Existing timing, Feibot, results-broadcast and event-sync paths remain
available and do not start packet LAN implicitly.

The packet schemas are additive and shared with RUN5 and Stopwatch. Old Desk
and Stopwatch releases do not understand packet issuance; mixed versions must
fail closed instead of downgrading credentials, operations or feed cursors.

## Verification and remaining gates

The exact source branch passes production frontend build, deadline regression,
ordinary and Edge Chromium smoke, formatting, vet, staticcheck, Go tests and
race tests with the pinned Go 1.24.13 toolchain and source-addressed rfid-core.
The coordinated Stopwatch candidate passes its deterministic package gate and
real-Chromium storage, UI, connection, 20,000-registration and four-independent-
client RUN5 receiver suites.

Publication remains blocked on all of the following:

- Android and iPhone installation, local-CA trust and mDNS acceptance;
- a real competition-Mac restart and saved packet-LAN recovery;
- the two-hour, four-tablet outage/reconnect/conflict/resource runbook;
- the explicit Go 1.24/macOS 11 dependency-security decision;
- exact tag CI artifacts and receiver-first deployment authorization.

Rollback is non-destructive: disable invitations/capability, stop packet LAN,
retain the complete Desk data directory and tablet backups, and restore the
previous application. Do not delete pending operations or feed history to make
a rollback appear successful.
