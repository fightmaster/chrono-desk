# Chrono Desk — нехватка бекенда/функционала под новый UI

Новый UI собран на существующем фронтенде (Svelte 3) и переиспользует текущие
REST-эндпоинты. Ниже — места, где макет/ТЗ требует данных или функций, которых в
бекенде нет. Сгруппировано по приоритету.

Легенда статуса в UI:
- **обходной путь** — сейчас работает, но через костыль на клиенте;
- **только отображение** — функция показана, но не редактируется/не сохраняется;
- **отсутствует** — в UI заглушка или поведение неполное;
- **✅ реализовано** — закрыто, оставлено для истории.

## P1 — функциональные пробелы (влияют на сценарий судьи)

### 1. Ручной захват времени «⏱ Зафиксировать время» не персистится
- **Где:** Live → «Зафиксировать время»; карточка-drawer (режим ручного финиша).
- **Сейчас (обходной путь):** захваты без номера хранятся только в памяти приложения
  (`captures` в `App.svelte`). При перезагрузке/перезапуске они **теряются**, не
  попадают в журнал правок и не синхронизируются. Привязка номера в drawer уже
  персистит через `POST /members/{id}/manual-finish` (`time_ms` = астрономическое
  время), а до привязки записи нет нигде в БД.
- **Нужно от бекенда:** хранилище «висящих» захватов без участника — например, строка
  `results` с NULL `member_id` (или отдельная таблица `pending_captures`) и эндпоинты:
  - `POST /api/events/{id}/captures` `{time_ms}` → создать;
  - `GET /api/events/{id}/captures` → список (для восстановления ленты);
  - `DELETE /api/events/{id}/captures/{capId}` → удалить;
  - `POST /api/events/{id}/captures/{capId}/bind` `{member_id}` → привязать (создать
    manual-finish и удалить захват) — или оставить привязку через текущий manual-finish.
  - Желательно журналировать (`local_changes`) и включать в синхронизацию на сайт.

## P2 — данные, которых не хватает (есть обходной путь)

### 4. Счётчики на списке событий (`N дистанций · M участников`)
- **Где:** стартовый экран «События», подпись карточки.
- **✅ реализовано:** `EventInfo` (`GET /api/events`) теперь отдаёт `race_count` и
  `member_count` (один лёгкий запрос на событие при листинге). Клиент больше не
  догружает полные списки гонок/участников ради `.length` (убран N+1).

### 5. «финишировало X из Y» в шапке дистанции
- **Где:** Результаты, мета под названием дистанции.
- **Сейчас (обходной путь/эвристика):** считаем на клиенте по протоколу —
  `финишировало = строки c place != null`, `всего = строк`. Это не обязательно
  совпадает с «стартовало/финишировало» в терминах сайта.
- **Нужно от бекенда (опц.):** авторитетные счётчики стартовавших/финишировавших в
  ответе протокола, если нужна точность.

## P3 — мелочи / решения по продукту

### 6. Индикатор LIVE в шапке — через polling
- Пульсирующая точка/подпись в шапке берётся опросом `GET /live/status` раз в 3 с
  (плюс свой опрос на самом Live-экране раз в 2 с). Работает, но это polling.
- **Опц.:** SSE/websocket или встроить статус приёма в другой общий ответ.

### 7. Тип чекпоинта (`type`) не редактируется у существующих строк
- В таблице чекпоинтов тип меняется только при создании; у существующих строк он
  только отображается (как и в старом UI). Если нужно менять тип готового чекпоинта —
  проверить, поддерживает ли `POST /edits` поле `type` для `entity=checkpoint`.

### 8. Дистанция в результатах глобального поиска
- В выпадашке поиска по событию макет показывает дистанцию участника; сейчас показываем
  метку (EPC). Можно мапить `member.race_id` → имя гонки на клиенте (данные есть) —
  это правка фронта, не бекенда. Отметил для полноты.

## Закрыто / снято

### 2. Грамоты (печать/экспорт призёров) — снято
- **Где:** Результаты → вкладка «Призёры · грамоты».
- Вкладка уже даёт хорошее отображение топ-3 абсолюта и призёров по группам — этого
  достаточно. Генерация под печать (PDF/Excel-шаблон) **не требуется**: на соревновании
  нет принтера. Снято с задач; при появлении принтера можно вернуть как «красивый
  экспорт под печать».

### 3. Возрастные группы — ✅ реализовано (per-race привязка из каталога)
- **Где:** Результаты → «Настройки дистанции» → «Возрастные группы».
- **Было:** категории показаны статичными чипами, event-global, одинаковые на всех
  дистанциях; нельзя добавить/привязать.
- **Стало:** экспорт сайта (`schema_version 2`) везёт **полный каталог категорий** +
  pivot `category_races` (run5 `category_race`). В десктопе появилась таблица
  `race_categories`:
  - выпадашка категории у участника и чипы дистанции берут **привязанный к гонке набор**
    (`GET /races/{raceID}/categories`), а не весь каталог — у участника снова видно
    только нужные;
  - «+ добавить из каталога» привязывает существующую категорию к дистанции
    (`POST /races/{raceID}/categories`), detach — `DELETE .../categories/{categoryID}`
    (запрещён, пока в категории есть участники этой гонки);
  - attach/detach журналируются (`race_category` `_attached`/`_detached`), переживают
    реимпорт (replay в `ReapplyLocalEdits`) и синхронизируются на сайт
    (`category_attaches` из живого pivot, `category_detaches` из журнала; на run5 —
    `syncWithoutDetaching` / overwrite-gated detach).
- **Остаточный (отложено):** создание категории, которой **нет даже на сайте**
  (придумали на месте) — по шаблону `checkpoint_creates` (`local-` id + матч по
  сигнатуре + ремап на apply). Для «забыли привязать существующую» не требуется.

## Чего НЕ хватало, но оказалось на месте (проверено)
- Протокол отдаёт `gender`, `gender_place`, `category_place`, `category_name`,
  `clean_time`, `place`, `status`, `number`, `member_id` — вкладки «Призёры» и
  «Протокол» работают без доработок бекенда.
- Ручной финиш по номеру (чистое/время суток), удаление ручного результата,
  включение/отключение лога, правки участника/старта/статуса, чекпоинты CRUD,
  импорт CSV (с обязательной tz), экспорт JSON/Excel/бэкап, синхронизация push/pull —
  всё уже есть, переиспользовано как есть.
- `manual-finish` возвращает `result_id` → кнопка «Изменить номер» в drawer корректно
  удаляет ошибочно созданный ручной результат и возвращает поиск.
